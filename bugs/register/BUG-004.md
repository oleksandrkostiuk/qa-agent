# BUG-004: Freshly registered user cannot log in — registration does not persist the account

**Test Case:** TC-REGISTER-POSTLOGIN-002
**Feature:** register
**Flow:** login-after-registration
**Priority:** High
**Severity:** Critical
**Date Found:** 2026-10-05
**Source Report:** reports/register-2026-10-05-143606
**Jira:** [STG-722](https://elekshelp.atlassian.net/browse/STG-722)

## Description
`POST /api/user/` returns `200 OK` for a brand-new registration, but the account is never actually persisted: a subsequent `GET /api/user/validateUserName/<username>` still reports the username as available, and logging in with the just-registered credentials returns `401`. This was reproduced twice with two different freshly-generated usernames, so it is not an isolated flake. Net effect: no newly registered user can ever log in — the registration feature appears to succeed but silently does nothing, which blocks the entire register → login journey for every new user.

Likely the same underlying defect as BUG-005 (TC-REGISTER-USERNAME-006) — `POST /api/user/` returning `200` without writing a real user record would also explain why duplicate-username registration isn't rejected there.

## Steps to Reproduce
1. Register a new account via `POST /api/user/` with a fresh, never-used `userName` (registration responds `200 OK`).
2. Send `POST /api/login/` with that same `userName` and its password.

## Expected Result
Response status is 200; response body contains a "token" field and a "userDetails" object with "userId" and "username" matching the registered account.

## Actual Result
Attempt 1 (userName=qa_postlogin_1791200085, password=Passw0rd1): registration returned 200, but `GET /api/user/validateUserName/qa_postlogin_1791200085` still reported the username as available (`true`) — the account was never persisted. Login returned 401.
Retry with a second, independently-generated account (userName=qa_postlogin2_1791200149, gender=Male): registration again returned 200, validateUserName again showed the username as still available, and login again returned 401.

## Request/Response
Request: POST /api/login/
Headers: { "Content-Type": "application/json" }
Body: { "userName": "qa_postlogin2_1791200149", "password": "Passw0rd1" }

Response: 401
Body: (empty)
